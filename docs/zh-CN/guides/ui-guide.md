# 界面指南

**简体中文** | [English](../../en/guides/ui-guide.md) | [文档中心](../README.md)

dsh-mnemon 出现在三个地方：对话里能看到每一轮用了哪些记忆；**记忆系统**用来浏览和编辑已保存的内容；**插件**中的“可组合记忆”页面负责组合记忆与修改设置。

| 位置 | 在这里做什么 | 如何打开 |
|---|---|---|
| [在对话中](#在对话中) | 查看一条回复背后的记忆；把回复存入记忆 | 每条已完成回复的下方 |
| [记忆系统](#记忆系统) | 查看状态；浏览、检索、编辑运行时记忆、项目档案与记忆空间 | 侧栏中的**记忆系统**，或会话标签页 |
| [在插件页中](#在插件页中) | 选择策略与增强；设置组件、存储与界面 | **插件 → 可组合记忆**，或记忆系统顶栏的齿轮 |

截图来自 [v0.5.17 图集](../../assets/webui-v0.5.17/README.md)：真实 WebUI 的浅色界面，数据是预置的虚构项目 Lumen。[观看 31 秒演示](../../assets/webui-v0.5.17/zh-CN/demo.mp4)。

有两条规则处处适用：**开关与选择器改动后立即生效**，写入失败时控件恢复为已保存的值，并在旁边说明原因；**需要输入的值等待所在分组的“应用”**，有改动时才出现，并说明应用后会发生什么。

## 在对话中

![一条回答同时用到工作记忆、记忆空间与项目档案，回合记忆栏已展开](../../assets/webui-v0.5.17/zh-CN/chat-recall.jpg)

### 回合记忆栏

用到记忆的回复末尾会有一行**本回合记忆**，列出这一轮的召回、档案检索与写入次数，展开后可以看到具体工具。图中 Agent 检索了一次项目档案、从记忆空间召回了两次；它引用的目标来自工作记忆，分层策略让工作记忆常驻每一轮。点击工具会打开记忆系统中对应的页面。没有记忆活动的回合不显示这一行。

![一次修正写入工作记忆，回合记忆栏显示一次沉淀](../../assets/webui-v0.5.17/zh-CN/chat-correction.jpg)

纠正某个事实时，Agent 可以替换对应的运行时记忆，回合记忆栏会记下这次写入。临时进度、猜测和密钥不会被写入。

### 存入记忆

每条已完成回复的操作栏里都有**存入记忆**。第一次点击只读取这条回复并打开可编辑的对话框，“取消”不会改动任何数据；确认后，文本交给独立任务 Agent，由它判断是否值得保存、选择最合适的记忆空间、去重后写入。

这两项默认开启，可以在[界面](#界面)中关闭。以会话标签页方式打开时，快捷入口会打开来源会话中的记忆系统标签；分屏里有多个候选标签时，请手动打开目标标签。

## 记忆系统

记忆系统有四个页面，名称来自提供它们的组件：**状态**、**运行时记忆**、**项目档案**和**记忆空间**；安装的 Source 也会以同样方式加入自己的页面。顶栏显示连接状态与正在组合记忆的主策略（例如“已连接 · 分层策略”）、存储范围、刷新按钮，以及打开插件页的齿轮。

记忆系统默认位于侧栏，回来时停留在原来的页面。在**界面 → 记忆系统入口**中选择**会话标签页**，即可改为在会话内打开，页面完全相同。**返回会话**或 Esc 回到对话。

### 状态

![状态页：记忆引擎、每个记忆组件一张卡片，以及 Provider 列表](../../assets/webui-v0.5.17/zh-CN/memory-status.jpg)

第一行每个组件一张卡片：先是记忆引擎及其版本，然后是各个 Source 保存的内容，图中为 3 条用户画像与 5 条工作记忆、5 份活跃档案与 1 份归档、3 个记忆空间中 2 个已激活。下方是记忆 Provider 及其健康状态，再往下是存储区域与版本。各区域独立加载，一处失败不会遮住其他内容。

只有记忆需要处理时，页面上方才会出现带**前往配置**的提示：

- **记忆未生效**：没有主策略在运行，对话会在没有记忆的情况下继续。
- **所选主策略没有运行**：暂时由另一个策略组合记忆。
- **最近的组件变更没有生效**：继续使用之前的组合。

**检查版本**只读取信息：它会说明 Mnemon CLI 是缺失、最新还是可更新，并给出可复制的 npm 命令；还会列出每个子包的已安装、已发布与锁定版本。更新包后请重启 `dsh web`。

### 运行时记忆

![运行时记忆：USER.md 与 MEMORY.md 及其条目](../../assets/webui-v0.5.17/zh-CN/memory-runtime.jpg)

运行时记忆是每一轮都会注入的紧凑上下文。**用户画像**（`USER.md`）记录你是谁、你的偏好与协作规则；**工作记忆**（`MEMORY.md`）记录项目事实、环境、决策与经验。每张卡片显示已用大小与上限。

- 条目按时间倒序排列，可以按目标、文本与重要性筛选；编辑旧条目不会改变它的位置。
- 条目应简短、相互独立、会被反复用到；临时进度和原始日志不应放在这里。
- 工作记忆条目可以限定 git 分支，只有会话工作区处于这些分支时才会注入；页面和磁盘上的文件不受影响。
- 工作记忆达到上限时，宿主会先把最旧的条目归档到记忆空间，再添加新条目。

<details>
<summary>编辑、容量与分支细节</summary>

“编辑”和“移除”在所属目标中按完整内容匹配条目，因此可以只修改简短的 `X`，而不影响 `EGO_LINUX_CHROME`。同一目标中完全相同的条目无法区分，会被拒绝且不改动数据。

容量归档移动的是原始条目。某一批路由失败或返回无效提案时，这一批会写入符合条件的默认记忆空间或第一个符合条件的空间，摘要中会记录原因。当前回合创建或激活的空间，在激活并支持写入后也可以接收归档。没有可用目标时，已有条目保持不变，待添加的条目也不会保存；排除原因后重新提交即可。

Agent 写入用户画像时，`branches` 必须省略或为空。对工作记忆执行替换时，`branches: []` 会清除分支限定，省略则保持原样。面向模型的快照会为每个条目附上重要性与天数，只作用于新的一轮，不改变已保存的文本。参见[投影格式与上限](../reference/storage-model.md#事实源和投影)。

</details>

### 项目档案

![项目档案：目录与阅读器中的架构决策](../../assets/webui-v0.5.17/zh-CN/memory-documents.jpg)

项目档案保存完整的叙事：设计、调查、流程与交接。请先选择 DSH 工作区；即使使用全局存储，档案也属于某个工作区。

- 在**活跃档案**与**归档**之间切换；阅读器保留标题、检索描述、来源、修订、哈希、大小与完整 Markdown。
- 检索会匹配标题、描述与正文；列表按创建时间倒序，更新旧档案不会把它移到最前。
- 项目中的源文件永远不会被修改，档案是受管理的副本。
- 归档会先在记忆空间中为档案建立索引，再移动原文件，因此冷数据仍然可以检索到；目标空间必须已激活，并支持精确写入与安全遗忘。

<details>
<summary>归档与后台审查细节</summary>

显式归档或容量维护时，一个没有记忆工具的独立任务 Agent 会提出摘要和一个符合条件的记忆空间。宿主校验后补充冷存储路径与内容哈希，写入索引并记录来源，然后才移动原文件。提案无效时不改动任何数据。移动失败时，宿主只删除刚刚创建的索引；已有且经过验证的索引会被复用，不会被删除。清理失败或 Provider 结果不确定时，请先检查报告中的目标再重试。

后台审查不会修改已有档案：它先检索，跳过已覆盖的内容，只在有大量新知识时另建补充档案；容量不足时直接跳过。它复用已完成对话中已有的证据，不能重新打开文件。

</details>

### 记忆空间

![记忆空间：目录中两个已激活、一个未激活的空间](../../assets/webui-v0.5.17/zh-CN/memory-spaces.jpg)

记忆空间是某个 Provider 上一个具名的长期证据范围。**概览**以卡片列出各个空间：卡片上的开关决定 dsh-mnemon 是否读取它，标签显示所用的 Provider（Mnemon Native 显示为 `mnemon`）；点击卡片只重连这一个空间。右上角是**沉淀记忆**与**沉淀策略**，概览旁边是**检索**、**内容**与**实体**。

![已激活空间的图谱，选中了 ClickHouse 实体](../../assets/webui-v0.5.17/zh-CN/memory-graph.jpg)

卡片下方的图谱合并了各个已激活空间能提供的内容：记忆、实体以及它们之间的连接。选中空间、实体或记忆，右侧会显示它的上下文，图中是 ClickHouse 实体：被引用 5 次，并提供**围绕它检索**。布局、拖动与重置只改变显示方式。底部统计空间、记忆与实体的数量，以及当前绘制的元素数。

每个空间都会声明其 Provider 真正能提供什么：Mnemon Native 提供带类型的关系；Hindsight 与 Holographic 提供各自的图谱；没有关系边的 Provider 只贡献内容；ByteRover 这类仅支持查询的 Provider 要等你提问。不支持的能力不会被凭空补出来。

- **创建记忆空间**时总是要求你选择 Provider，只列出在[记忆空间页面](#memory-spaces-page)中启用的 Provider。
- **沉淀策略**决定之后 Agent 写入的去向：**手动**使用你指定的目标，尚未保存时使用第一个就绪的 Provider；**智能选择**把数据边界与必需能力作为硬性规则，再参考你的偏好，只有多个候选都符合时才调用模型。
- **AI 维护元信息**会对选中的每个空间取样，建议标题与说明；各空间独立运行，失败只显示在对应卡片上。

#### 检索

![直接检索：在已激活空间中检索，带分数与来源](../../assets/webui-v0.5.17/zh-CN/memory-recall.jpg)

**直接检索**不经过 Agent，直接返回各个已激活空间的原始证据，保留各 Provider 自己的分数、ID、空间与分类。**Agent 查询**先做同样的检索，再把证据交给只读的任务 Agent 作答。各 Provider 并行返回，一处失败不会遮住其他结果。**查看关联**、**关联**、**浏览**与**忘记**只在 Provider 支持时出现。具体的问题通常比零散的关键词更可靠。

#### 内容与实体

![实体：选中 ClickHouse，列出提到它的记忆](../../assets/webui-v0.5.17/zh-CN/memory-entities.jpg)

**内容**在 Provider 可以枚举时列出记忆，并标出仅支持查询的空间。**实体**只使用真正的实体索引，目前是 Mnemon Native、Hindsight 与 Holographic；选中一个实体，会跨空间汇集提到它的记忆。[内容页截图](../../assets/webui-v0.5.17/zh-CN/memory-content.jpg)。

#### 沉淀记忆

![沉淀记忆：由独立任务 Agent 判断并写入候选内容](../../assets/webui-v0.5.17/zh-CN/memory-remember.jpg)

通常只需写下候选内容。确认后，一个没有会话历史的任务 Agent 会判断它是否值得保存、选择最合适的空间、去重、提炼并写入。只有确实需要限定目标、分类或重要性时，才使用人工高级选项。

## 在插件页中

![插件中的可组合记忆页面：标题、记忆组合与组件行](../../assets/webui-v0.5.17/zh-CN/plugin-composition.jpg)

| 位置 | 包含 | 生效方式 |

### 记忆组合

![主策略选择器：分层策略与通用策略](../../assets/webui-v0.5.17/zh-CN/plugin-strategy-menu.jpg)

- **主策略**是一个选择器，列出每个已安装的主策略及其说明。**分层策略**让运行时记忆常驻，按需读取项目档案与记忆空间，并执行后台维护；**通用策略**在同一份预算内提供全部可用来源，由模型决定如何使用，不做自动审查与容量维护。
- 下面是**记忆来源**与**增强**，每个组件一行，显示状态、开关，有自己设置的组件还有齿轮。标签写明这一行依赖的组件或依赖它的组件，点击即可打开对应页面。
- 只有记忆没有按你的选择组合时，才会出现一行问题说明，并给出能解决它的那个开关。

每个开关都作用于之后的回合，已经开始的回合保留原有的 View。打开一个组件时，它依赖的组件会一起打开，不能与它共存的组件会被关闭；关闭一个组件时，依赖它的组件也会关闭；选择一个主策略时，其他主策略会被关闭。最后一个运行中的来源不能关闭。开关影响到其他组件或改变了组合方式时，DSH 会弹出提示，并提供**撤销**。

### 组件页

![分层策略页面及其后台任务](../../assets/webui-v0.5.17/zh-CN/plugin-layered.jpg)

行上的齿轮、**主策略**旁边的齿轮，以及任何位置出现的组件名称，都会打开该组件的页面。页面显示组件的状态与开关、它是随附组件还是来自已安装的包、它依赖什么、谁依赖它、不能与谁共存、声明的选项以及它自己的设置；关联组件在原处打开，可以**返回**。选项会按宿主的限制校验，有改动时才出现**应用**，**恢复默认**可以还原单个选项。

<a id="memory-spaces-page"></a>

![记忆空间页面：Mnemon Native 与各第三方 Provider](../../assets/webui-v0.5.17/zh-CN/plugin-spaces.jpg)

- **运行时记忆页面**：**用户画像范围**。“全局共享”把全局的 `USER.md` 与工作区或自定义目录中的 `MEMORY.md` 组合使用，不移动任何一方。
- **记忆空间页面**：**记忆 Provider**。Mnemon Native 排在第一位，展开后只包含它的嵌入设置；每个第三方 Provider 都有自己的开关且默认关闭，打开后才显示服务地址、密钥等字段。“全局”或“工作区”标签表示实际作用范围。OpenViking 的 **User Key 所属用户（跳过 Admin）** 用于没有 Admin 权限的密钥，参见[其限制](./memory-providers.md#运维边界)。
- **分层策略页面**：**后台任务**。**任务 Agent 模型**默认跟随 DSH 新会话的默认链路，也可以**指定模型**，选择一对完整的 Provider 与模型；它作用于 AI 维护元信息、Agent 查询、沉淀记忆、智能路由与档案归档，不会改变主对话的模型。**空闲审查**、审查方式与 Agent Teams 兼容模式立即生效，**审查参数**点击**应用**后生效。审查只在分层策略组合的回合之后运行，参见[配置](../reference/configuration.md#provider-要求)。

<details>
<summary>Mnemon Native 嵌入</summary>

展开 Mnemon Native 卡片。**由 DSH 管理嵌入配置**打开后，已保存的服务地址、模型、协议和可选密钥会成为 Mnemon 子进程的唯一配置，包括不读取 shell 启动文件的桌面端启动；这些字段随后显示，并通过**应用**一起生效。自动协议选择把以 `/v1` 结尾的地址视为 OpenAI 兼容，其他地址需要明确选择协议。地址中不能包含凭据、查询参数或片段。记忆与查询文本会发送到所配置的服务。**测试状态**检查的是已保存的值，而不是未保存的草稿。开启前请阅读[嵌入配置](../reference/configuration.md)。

</details>

### 存储

![存储：范围、默认数据目录、备份，以及界面设置](../../assets/webui-v0.5.17/zh-CN/plugin-storage.jpg)

**存储**先列出把数据保存在这个目录中的组件，点击名称即可打开对应的组件页。

- **存储范围**：**全局**让所有工作区共用一个目录；**工作区**把每个工作区的记忆放在它自己的 `.mnemon` 中；**集中存储 · 按工作区隔离**在同一个根目录下为每个工作区建立 `workspaces/<工作区路径哈希>/`。
- **数据目录**：在**默认**与**自定义**之间选择，这一行只显示记忆正在使用的一个目录。默认目录是 `MNEMON_DATA_DIR` 或 `~/.mnemon`；自定义时填写绝对路径或以 `~/` 开头的路径，集中存储下它是根目录。输入框留空只表示尚未填写，回到默认目录请选择**默认**。
- 范围与目录一起点击**应用**，应用前会说明后果：记忆改为读写新位置，已有数据不会被移动、合并或删除。

![备份与迁移：导出的 ZIP 在安全导入前的预览](../../assets/webui-v0.5.17/zh-CN/plugin-backup-preview.jpg)

## 查看的工作区与执行的工作区

| 概念 | 由谁选择 | 影响 |
|---|---|---|
| **查看的工作区** | 记忆系统顶栏 | 页面显示和编辑哪个 `<workspace>/.mnemon` |
| **执行的工作区** | 当前对话的工作目录 | 对话工具、命令与生命周期钩子使用哪个根目录 |

你可以在项目 A 的对话中查看项目 B。对话仍然作用于 A；从记忆系统发起的 AI 维护元信息、Agent 查询、沉淀记忆与档案归档，会以限定于 B 的任务 Agent 运行。远程 Provider 的命名空间不会随 DSH 工作区变化。全局与自定义存储只对应一个根目录，无需对齐。

## 主题与皮肤覆盖

皮肤作者可以先阅读[皮肤开发与 Mnemon 集成](../development/skin-integration.md)，其中有示例、从生成类名迁移的方法以及在真实 WebUI 中的验证步骤。本节定义受支持的契约。

侧栏与会话标签页使用同一个工作区根元素：`[data-dsh-plugin="dsh-mnemon"][data-dsh-part="mnemon-view"]`。请直接在该元素上设置以下自定义属性；设置在祖先元素上的值会被工作区默认值覆盖。生成的 CSS module 类名不是公开选择器。

| 属性 | 可接受的值与用途 | 默认值 |
|---|---|---|
| `--mn-bg` | 基础表面的 CSS 颜色 | `var(--dsw-alias-bg-base)` |
| `--mn-backdrop` | 默认分层表面中位于基础色之后的 CSS 颜色 | `var(--dsw-alias-bg-overlay, var(--mn-bg))` |
| `--mn-surface` | 工作区、顶栏与画布使用的 CSS `background` 值 | 基础渐变叠加在背景渐变之上，并以基础色兜底 |

默认表面为 `linear-gradient(var(--mn-bg), var(--mn-bg)), linear-gradient(var(--mn-backdrop), var(--mn-backdrop)) var(--mn-bg)`。当皮肤把宿主基础色设为透明时，这层叠加保证文字依然清晰；官方主题保持不透明。皮肤可以整体替换这一组合，例如：

```css
[data-dsh-plugin="dsh-mnemon"][data-dsh-part="mnemon-view"] {
  --mn-bg: rgb(232 241 249 / 74%);
  --mn-backdrop: var(--mn-bg);
  --mn-surface: var(--mn-bg);
}
```

请在未分层（unlayered）的样式表中使用这对选择器。它的优先级 `(0,2,0)` 高于默认声明的 `(0,1,0)`，无论皮肤样式先于还是晚于 Mnemon 加载都能生效。单独的 `[data-dsh-part="mnemon-view"]` 与默认值优先级相同，取决于加载顺序；写在 `@layer` 中的普通声明低于未分层的默认值。需要激活范围时，请加上皮肤自己的祖先选择器。挂载到 body 的对话框与其他插件的根元素不在此范围内。替换 `--mn-surface` 意味着由皮肤自行负责可读性与透明度，它不会改变设置、记忆数据或 Provider 行为。

## 通用规则

- 主要操作使用 DSH 主按钮，编辑等次要操作使用描边按钮；红色只用于删除、断开、归档与忘记。
- 记忆空间的开关只决定 dsh-mnemon 是否读取它，与 Mnemon CLI 的默认 Store 无关。
- 删除 Mnemon Native 空间需要确认；外部空间使用“断开”，不会改动 Provider 中的数据。
- 反复点击（包括选择已选中的值）都不会让页面变空白。
