Each memory component's own settings now live on its page, which the gear on its row opens: Runtime Memory holds where its user profile (USER.md) lives, Memory Spaces holds the Memory providers and the Mnemon Native embedding, and Layered strategy holds the task Agent model and idle review. The configuration keeps only what belongs to no component: Memory composition, Storage and Interface. Installed components add their own settings to their pages the same way, with `installMemoryComponentUI` from `dsh-mnemon/client`, which registers into the `mnemon.component.settings` region by package name. Interactions follow one rule everywhere: a gear marks a component with settings of its own, and the gear, the component's name, a relation chip or a name on another page opens that component's page, the last one in place with Back; switches and selectors apply when they change and show the saved value again beside the reason if a write fails; typed values wait for their group's Apply, which appears only once something changed, and the page stays open after it. Storage names the components that keep their data in its directory, shows where memory lives now, and says beside its Apply that existing data is not moved. Idle review's interval reads in seconds, Providers that share a name show their ids, and settings in a component page no longer overflow the dialog. The Memory System names its tabs, Status cards, storage areas and the header's main Strategy as the components declare themselves, so Runtime memory and Project Documents read the same on every page; every Source component has a Status card, contributed with `installMemoryComponentUI` through the `mnemon.component.status` region the way the shipped Sources contribute theirs, or saying that it runs. Each component row the Starter lists on DSH's own page opens a page of its own with the same component page. Descriptions are shorter throughout. Configuration keys, stored values and data are unchanged.

每个记忆组件自己的设置移到它的组件页中，点击该组件行内的齿轮即可打开：运行时记忆页包含用户画像（USER.md）的保存位置，记忆空间页包含记忆 Provider 与 Mnemon Native 嵌入，分层策略页包含任务 Agent 模型与空闲审查。配置页只保留不属于任何组件的内容：记忆组合、存储与界面。已安装的组件以同样方式把自己的设置加入组件页：使用 `dsh-mnemon/client` 的 `installMemoryComponentUI`，按包名注册到 `mnemon.component.settings` 区域。交互在各处遵循同一规则：有自己设置的组件显示齿轮；点击齿轮、组件名称、关联标签或另一组件页中的名称，都会打开对应组件页，最后一种在原处打开并可返回；开关与下拉选择改动即生效，写入失败时恢复为已保存的值并就地说明原因；需要输入的值按组点击“应用”，改动后才出现，应用后页面保持打开。“存储”列出数据保存在其目录中的组件，显示当前所在位置，并在“应用”旁说明已有数据不会迁移。空闲审查的间隔改以秒显示，同名的 Provider 附上 id 区分，组件页中的设置不再超出弹窗。记忆系统的标签页、状态卡片、存储区与页头主策略都按组件声明的名称显示，“运行时记忆”“项目档案”在各页面名称一致；每个 Source 组件都有状态卡片：通过 `installMemoryComponentUI` 在 `mnemon.component.status` 区域提供内容（随附 Source 也这样提供），未提供时显示正在运行。Starter 在 DSH 页面中列出的每个组件行都能打开自己的页面，其中是相同的组件页。各处说明文字更短。配置键、已保存的值与数据不变。
