The Starter no longer lists a separate `dsh-mnemon/starter` row on the Plugins page. Its component group (`mnemon-bundle`, now the module `dsh-mnemon/bundle`) makes the Starter's dependency closure visible and then mounts the components with DSH's own `cordis:group`, so Enable now still works without a restart, and there is no readiness switch left that can hold the group back. In 0.5.18 and 0.5.19, turning that row off kept every component waiting for `mnemonStarterReady`: `dsh web` started without the Memory System and the desktop app treated it as a failed start. A leftover `- id: mnemon-starter` row in a profile patch no longer matches anything and is ignored. The container row now reads `dsh-mnemon/bundle` instead of `cordis:group` and, as before, DSH shows it as off. DSH's config schema export (`dsh web --dump-config-schema`) accepts only native groups, so it now reports `mnemon-bundle` as an unrecognized carrier and leaves Mnemon's component schemas out, as it does for DSH's own agent presets; runtime configuration and profile patches are unchanged.

Starter 不再在插件页单独列出 `dsh-mnemon/starter` 一行。它的组件组（`mnemon-bundle`，现为模块 `dsh-mnemon/bundle`）先让 Starter 的依赖可被解析，再用 DSH 自己的 `cordis:group` 挂载各组件，因此“立即启用”仍无需重启，也不再有能让组件组卡住的就绪开关。在 0.5.18 与 0.5.19 中，关闭那一行会让全部组件一直等待 `mnemonStarterReady`：`dsh web` 启动后没有记忆系统，桌面版则按启动失败处理。profile patch 中残留的 `- id: mnemon-starter` 不再对应任何条目，会被忽略。容器行显示为 `dsh-mnemon/bundle`，不再是 `cordis:group`，DSH 仍与以前一样显示它为已关闭。DSH 的配置 schema 导出（`dsh web --dump-config-schema`）只接受原生 group，现在会把 `mnemon-bundle` 报告为无法识别的树载体，并略去 Mnemon 各组件的 schema，与 DSH 自带的 agent preset 相同；运行时配置与 profile patch 不受影响。
